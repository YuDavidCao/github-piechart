# PRs by repo

Embeddable SVG pie chart of any GitHub user's pull requests, grouped by repo.

```markdown
[![PRs by repo](https://YOUR-DEPLOY.vercel.app/api/pie?username=octocat&range=1y)](https://github.com/octocat)
```

Counts the last year by default; the card's caption always states the window it used.

Counts come from GraphQL `contributionsCollection`: exact per-repo totals in one request per
year of range, costing a single rate-limit point each (5000/hour). Private repos are absent
from those breakdowns, and any that appeared would be dropped — a public card must never
name one.

| Param | Default | Notes |
|---|---|---|
| `username` | — | required |
| `by` | `pr` | what to count — `pr`, `commit`, `issue`, `review`, or `all` |
| `private` | `false` | adds one lump slice for private-repo work; requires `by=all` |
| `range` | `1y` | window to count over — `30d`, `6m`, `2y`, or `all` |
| `limit` | `6` | top N repos, 1–20; the rest collapse into one grey "N more repos" slice |
| `theme` | `light` | `light` or `dark` |
| `title` | `<user>'s PRs by repo` | |

Slice colours are generated by golden-angle hue rotation, so any `limit` gets distinct,
well-separated colours without maintaining a palette.

### `private=true`

GitHub exposes private work as a single `restrictedContributionsCount` — no repo names, no
per-type split, and it reads 0 unless the user has ticked **Include private contributions on
my profile** in their GitHub settings. It rides along on the queries already being made, so
it costs nothing extra.

Because that number mixes commits, PRs, issues and reviews, it only lines up with `by=all`;
any other mode returns an error card rather than putting non-PRs in a PR pie. Expect the
slice to dominate — private commits usually outnumber public contributions many times over.

`index.html` is a preview page that builds the embed snippet for you.

## Deploy

```sh
vercel deploy --prod
vercel env add GITHUB_TOKEN     # classic PAT, no scopes needed — public data only
vercel --prod                   # env vars only reach NEW deployments
```

`GITHUB_TOKEN` is **required** — GitHub's GraphQL API rejects anonymous requests. Without it
every card renders "This deploy is missing GITHUB_TOKEN". Responses are cached 2h
(`s-maxage`), and GitHub's camo proxy caches on top of that.

## Local preview

```sh
GITHUB_TOKEN=$(gh auth token) node dev.js   # http://localhost:3000
```

Serves `index.html` plus a live `/api/pie`, so you can try a card before deploying.

## Test

```sh
node test.js     # hits the live API, writes $TMPDIR/pr-pie.svg
```
